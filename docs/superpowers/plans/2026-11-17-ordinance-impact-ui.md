# 조례 변경 영향 검토 화면 시제품 구현 계획

> 사용자 요청: 기존 기초설계를 실제로 볼 수 있는 화면으로 진행한다. 기존 설계와 자율 진행 지시에 따라 현재 브랜치에서 실행한다.

**Goal:** 목록→근거 비교→정정안 승인→수정 확인을 클릭해 볼 수 있는 독립 화면을 만든다.
**Architecture:** 기존 React/TypeScript/Vite 도구를 사용한 별도 로컬 앱. 고정된 가상 사례와 메모리 내 상태만 사용한다.
**Tech Stack:** 기존 React, React Router, lucide-react, TypeScript, Vite. 새 라이브러리 없음.
**Spec:** ../../../DESIGN.md, ../specs/2026-11-17-ordinance-impact-design.md

## 범위와 결정

- prototype/ordinance_impact/web/에 분리하고 포트 5175로 실행한다.
- 기존 이음등의 상태·가구 데이터는 사용하지 않는다.
- 기본 화면은 변경 검토 목록, 핵심 상세는 전후 조문/현재 안내 3열 비교다.
- 연결 관리·출처·이력을 포함하되 실제 수집·AI 생성·외부 게시 기능을 구현했다고 표현하지 않는다.
- 모든 사례·원문·정정 초안은 가상이며 기준일은 2026-11-17로 고정한다.
- DESIGN.md의 밝은 중립 배경·청색 강조·본문 중심 밀도·키보드 접근 규칙을 따른다.
- 서버 연동 구현의 G0와 독립적인 화면 검토용 시제품이다.

## Review Focus

- 시행 예정·부칙 미확인·사업 연결 미확인 건은 승인할 수 없어야 한다.
- 승인과 실제 수정 확인은 별도 동작이다.
- 수정된 초안의 변경 값이 빠지면 승인을 차단한다.
- 좁은 화면에서 조문·버튼·표가 겹치거나 잘리지 않아야 한다.
- 오류·가상 상태를 실제 수집 성공·법적 판단으로 표시하지 않아야 한다.
