# 실제 공공데이터 연결 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 가상 시연과 구분되는 실제 데이터 탐색·원문 근거·수집 상태를 새 서비스에 연결한다.

**Architecture:** Python 수집기가 기존 캐시와 공식 출처 원문을 해시 기반 파일로 보존하고 catalog를 원자적으로 갱신한다. FastAPI 읽기 API와 React 데이터 화면은 공통 계약으로 병렬 구현한다.

**Tech Stack:** 기존 Python/FastAPI/Pydantic·표준 라이브러리·React/TypeScript/Vite. 새 의존성 없음.

**Spec:** [실제 공공데이터 연결 설계](../specs/2026-11-17-ordinance-data-integration.md)

## Global Constraints

- 기존 이음등 코드·원본 캐시·공모전 원본은 변경하지 않는다.
- 실제/캐시/가상, 출처 수집 실패와 상세 미확보를 구분한다.
- 인증키·토큰·환경파일·인증 query는 출력·저장·커밋하지 않는다.
- 자동 법률 판단·자동 승인·외부 게시는 구현하지 않는다.
- 정해진 공식 HTTPS 출처만 제한된 횟수와 크기로 수집한다.

## Review Focus

- 과거 자료를 오늘의 실시간 데이터로 표시하지 않는가.
- 기관별 상세/목록 구조 차이와 반복 근거법령을 보존하는가.
- 인증 오류/차단 HTML을 정상 원문으로 저장하지 않는가.
- 법규명 일치 후보를 검증된 법적 관계로 표시하지 않는가.
- API 장애 시 가상 자료로 성공을 가장하지 않는가.
