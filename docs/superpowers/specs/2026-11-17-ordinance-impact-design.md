# 조례 변경 영향 추적 및 안내 오류 예방 AI — 기초설계

- 버전: v0.1 / 2026-11-17
- 상태: 설계·가상 검토 시연과 실제 자료 수집·탐색 구현. AI 분석·오류 입증·성능 평가 전.
- 브랜치: design/ordinance-change-impact
- 범위: 이음등과 독립된 공무원 업무 지원 도구. 별도 서비스명은 아직 정하지 않는다.

## 1. 해결할 문제와 가설

조례 개정으로 복지사업의 신청 기한·거주 요건·연령·지원 금액이 바뀌었을 때, 관련 사업 설명과 안내자료에 변경이 반영되었는지 담당자가 확인하는 일을 돕는다.

**검증할 가설:** 조례와 사업·안내자료의 연결 관계를 보존하면 개정 때마다 확인할 자료를 찾기 쉬워지고, 변경 근거가 붙은 정정 초안이 검토 시간을 줄일 수 있다. 오류 발생 빈도와 업무 절감 효과는 아직 조사하지 않았다. 실제 사례가 확보되기 전에는 “현재 안내가 잘못되어 있다”고 주장하지 않는다.

비교 대상 수상작은 제공받은 제목만 확인했다. 아래 내용은 독립 제안이며 수상작의 실제 구현이나 기능을 추정하지 않는다.

## 2. 사용자와 결과물

| 사용자 | 해야 할 일 | 도구가 제공할 결과 |
|---|---|---|
| 복지사업 담당자 | 개정이 자기 사업에 적용되는지 판단 | 이전·개정 조문, 조건 변화, 부칙, 연결 사업 |
| 안내자료 관리 담당자 | 웹·안내문 수정 내용 검토 | 원문 위치, 불일치 후보, 근거를 인용한 정정 초안 |
| 법무·제도 검토 담당자 | 적용 시점·예외·위임 관계 확인 | 미해결 쟁점과 필요한 근거 목록 |

주요 산출물은 **변경 영향 검토 건**이다. 조례 버전쌍, 연결 사업, 안내자료 버전, 적용 판단, 조건별 비교, 담당자 결정과 수정 확인 이력이 하나로 묶인다.

## 3. 제품의 중심 결정

1. **조례 개정 사건에서 시작한다.** 현행 안내문을 한 번 검사하는 방식에서 확장해, 어떤 개정이 어떤 자료의 재검토를 발생시켰는지 추적한다.
2. **조례–사업 연결을 먼저 확인한다.** 복지 API의 근거법령명은 연결 후보를 만들 때 쓰고, 담당자가 확인한 관계만 승인 가능한 비교에 사용한다.
3. **등록 범위 안에서는 빠짐없이 비교한다.** 연결된 사업의 등록 안내자료 전체를 순회한다. 검색 상위 몇 개만 검사한 뒤 전체를 확인했다고 표시하지 않는다.
4. **숫자 변화와 적용 판단을 분리한다.** 90일→180일을 추출해도 시행일·부칙·안내자료의 대상 시기를 확인하기 전에는 오류로 확정하지 않는다.
5. **승인과 수정 완료를 분리한다.** 도구 안의 정정안 승인은 외부 문서 반영을 뜻하지 않는다. 재수집한 문서를 확인해야 수정 확인 상태가 된다.
6. **근거가 바뀌면 재검토한다.** 법규·사업 근거·연결·적용 판단이나 안내의 승인 범위 밖 내용이 달라지면 새 분석 회차를 만들고 과거 승인을 승계하지 않는다. 승인한 안내 수정 결과는 별도 후속 스냅샷으로 보존해 기존 승인과 비교한다. 예상한 수정만 반영되었다면 기존 회차를 수정 확인으로 종료한다.

국가법령정보 공동활용의 조례 목록·본문 문서에는 공포일, 시행일, 연혁, 조문·부칙 등의 제공 항목이 설명되어 있다. 복지 API의 근거법령 목록에는 직접 연결할 조례 ID/MST 전용 필드가 확인되지 않았다. [공식 자료 조사](../../../research/ordinance-impact-sources.md)의 확인 범위와 제한을 따른다.

## 4. MVP 범위와 진행 관문

| 항목 | 초기 목표 | 비고 |
|---|---|---|
| 지역 | 지자체 1곳 | 실제 원문 확보 후 선정, 특정 지역 확정 전 |
| 사업 | 복지사업 10개 | 조례 근거를 확인할 수 있는 사업 우선 |
| 법규 | 이전·개정 버전쌍 10개 | 서로 다른 조례 10개일 필요는 없음 |
| 안내자료 | 버전이 보존된 자료 20개 | 사업 API 설명과 공개 HTML 안내문 |
| 조건 | 명시된 신청 기한·거주 기간·연령 경계·지원 금액 | 단위·이상/초과·이하/미만 보존 |

위 수치는 **수집 목표**다. 확보·평가 완료 수치가 아니다.

**G0: 실제 연결 3건을 먼저 확보한다.** 각 건에 같은 지자체의 조례 이전·개정 원문, 사업 근거 연결, 비교할 안내자료, 적용 시점을 확인할 자료가 있어야 한다. 안내 오류가 없는 건도 유효하다. 3건이 확보되지 않으면 먼저 출처·범위를 조정하고 합성 시연만으로 실제 적용 가능성을 입증하지 않는다.

MVP에서 제외할 것:

- 전국 자동 감시, 모든 공개 안내문의 자동 발견, 외부 CMS 자동 게시
- 개인별 자격·수급·소급 적용 판단, 주민 개인정보와 내부 행정망 연결
- 소득인정액 계산, 복합 법률 해석의 자동 확정
- PDF/HWP OCR·표 해석의 자동 처리. 필요한 공식 첨부는 담당자가 출처·페이지와 함께 텍스트를 등록할 수 있다.
- 별표·상위법·시행규칙이 필요한데 확보되지 않은 조건의 확정 판정

## 5. 사용자 흐름

~~~mermaid
flowchart TD
    A[출처 등록·원문 버전 보존] --> B[이전·개정 조문 정렬]
    B --> C[조건 변화 후보 추출]
    C --> D[사업 연결 확인]
    D --> E[시행일·부칙·안내 대상 시기 검토]
    E --> F{근거 충분?}
    F -->|아니오| G[근거 확인 대기]
    F -->|예| H[등록 안내자료 전체 비교]
    H --> I[정정 초안과 근거 검토]
    I --> J[담당자 승인]
    J --> K[외부 안내자료 수동 수정]
    K --> L[재수집·수정 확인]
~~~

1. 수집 담당자가 지자체·법규·사업·안내자료를 등록한다. 수집일, 원문 URL, 본문 해시와 문서 시점을 저장한다.
2. 목록 또는 수동 입력으로 새 법규 버전을 발견한다. 동일 본문 재수집은 새 개정으로 만들지 않는다.
3. 조문 번호·제목·내용을 함께 이용해 전후를 정렬한다. 단순 조문 이동은 조건 변경과 구분한다.
4. 규칙과 AI가 조건 변화를 추출한다. 원문에 없는 수치·날짜는 채우지 않는다.
5. 확인된 연결 사업의 등록 안내자료를 비교한다. 미확인 연결은 별도 확인 목록에 둔다.
6. 검토자는 적용 조건·인용·정정안을 확인하고 승인·수정 요청·검토 제외를 결정한다.
7. 자료 관리자가 외부에서 수정하고 도구에서 다시 수집한다. 담당자가 반영 결과를 확인한다.

## 6. 날짜와 판단 규칙

| 구분 | 의미와 처리 |
|---|---|
| 공포일 | 개정 공표 시점. 즉시 적용이라고 간주하지 않는다. |
| 시행일 | 시행 예정/시행 중 분류의 기준. 조문별 예외가 있으면 별도로 기록한다. |
| 부칙의 적용례·경과조치 | 적용 대상 사건·신청 시점·예외를 검토한다. 미확인 시 승인 불가. |
| 사업 운영 기간 | 복지사업 API의 시행 시작·종료일. 조례 시행일과 같은 뜻이 아니다. |
| 안내자료 대상 시기 | 현재 안내인지, 과거 모집 공고·보관 문서인지 구분한다. |
| 수집 시각·판단 기준일 | 언제 확보했고 어느 날짜를 기준으로 판단했는지 표시한다. |

조례·시행규칙·연도별 공고가 충돌해 보이면 일률적인 우선순위로 덮어쓰지 않는다. 적용 근거와 위임 범위를 확인할 담당자에게 넘긴다. 구체적인 법률 해석은 검토자의 판단으로 기록한다.

목록은 “우선 검토”, “시행 예정”, “근거 확인”으로 구분한다. 임의의 종합 위험 점수를 만들지 않는다. 우선 검토에는 확인된 연결·적용 관계에서 현재 안내의 실질적 불일치가 의심되는 건을 둔다. 근거 확인 건수도 전체 화면에 표시한다.

## 7. AI와 일반 코드의 역할

| 일반 코드 | AI | 담당자 |
|---|---|---|
| 수집·해시·버전 보존, 관할 필터, 인용 일치 검사, 단위·날짜 정규화, 상태·권한 검증 | 조문 대응 후보, 조건 구조화, 영향 사유 요약, 정정 문장 초안 | 사업 연결 확정, 적용 조건 판단, 정정 승인, 실제 반영 확인 |

AI 출력은 정해진 스키마와 인용을 통과해야 저장 가능한 제안이 된다. 모델의 자체 확신도는 법적 확실성이나 승인 근거로 쓰지 않는다. 원문에 없는 항목은 미확인으로 남긴다.

## 8. 시연 시나리오

다음은 전부 **가상 A구·가상 복지사업** 예시다. 실제 조례나 발견된 오류로 제시하지 않는다. 기준일은 2026-11-17로 고정한다.

| 장면 | 입력 | 기대 결과 |
|---|---|---|
| 현재 안내 비교 | 신청 기한 90일→180일, 시행 2026-10-01, 별도 적용 예외 없음이 확인됨. 현재 안내에는 90일 | 관련 사업·자료와 양쪽 근거를 제시하고 “180일” 정정 초안 제안 |
| 시행 예정 | 같은 변화, 시행 2027-01-01 | 시행 예정 목록. 현재 안내를 곧바로 오류로 표시하지 않음 |
| 적용례 불명확 | 부칙에 시행 후 발생한 사건부터 적용, 안내 대상 사건 시기는 미확인 | 근거 확인 대기. 모든 신청자에게 180일로 고치는 초안 승인 차단 |
| 대조군 | 표현만 바뀌거나 다른 지자체의 동명 조례 | 실질 변화 없음 또는 연결 제외. 조용한 수집 실패와 구분 |

## 9. 개발 순서와 완료 기준

1. **데이터 가능성 확인:** 실제 연결 3건과 출처 권한·버전 확보. 실패하면 범위를 수정한다.
2. **근거 보존과 수동 비교:** 버전 저장, 확인된 관계, 조건 비교표와 검토 이력부터 동작시킨다.
3. **AI 제안:** 구조화 추출과 정정 초안, 인용 검사, 불충분 근거 보류를 추가한다.
4. **검토 화면:** 목록→근거 비교→승인→수정 확인의 한 흐름을 구현한다.
5. **평가:** 규칙 기반 비교 및 현행 본문만 보는 비교와 성능·오류·시간을 측정한다.

MVP 완료는 문서·가상 화면 작성 완료와 다르다. 실제 데이터 관문과 [검증 계획](../../08_validation-plan.md)의 기능·검토·안전 기준을 충족해야 한다. 현재 [실제 자료 연결](2026-11-17-ordinance-data-integration.md)과 [가상 검토 시연](../../../prototype/ordinance_impact/web/README.md)을 구분한다. 실제 조례 3쌍·사업·안내를 기술적으로 연결했지만 담당자 적용 판단·AI 분석·업무 성과 검증은 완료하지 않았다.

## 11. 미결정 사항과 담당

| 항목 | 확인 책임 | 결정 전 제약 |
|---|---|---|
| 실제 대상 지자체·사업·자료 | 데이터 조사 담당 | 전국 대응·데이터 확보 완료 주장 금지 |
| 연혁 버전 식별자 연결·별표 확보 | 수집 구현 담당 | 문서에 없는 보장 가정 금지 |
| 부칙·위임 규정 판단 예시 | 업무 검토 담당 | AI 단독 적용 확정 금지 |
| 모델·프롬프트·속도 | 시제품 구현 담당 | 특정 모델 성능·비용 확정 전 |
| 실제 기관 인증·보존 기간·게시 연동 | 도입 기관 담당 | 로컬 시연 범위에서 제외 |

각 담당은 역할이며 실제 참여자가 배정되었다는 뜻이 아니다.
