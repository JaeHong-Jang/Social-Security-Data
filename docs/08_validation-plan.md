# 검증 계획 v0.1

이 문서는 **앞으로 수행할 시스템·업무 검증**이다. 실제 데이터 연결은 별도 구현했지만 모델 평가·업무시간 측정 결과는 없다.
범위는 [기초설계](superpowers/specs/2026-11-17-ordinance-impact-design.md), 판정 기준은 [도메인 모델](05_domain-model.md)을 따른다.

가상 화면의 규칙 테스트 15개·브라우저 검사 36개·타입/빌드는 [화면 시제품](../prototype/ordinance_impact/web/README.md)에서 별도로 수행했다. 이는 G0·실제 원문·모델·기관 업무 검증의 완료를 뜻하지 않는다.

실제 수집기는 조례 전후 3쌍·제정본 1개, 상위법 1개, 복지로 안내 5건, 공개 통계 2,577행을 보존했다. 기존 사업 캐시 5,289건과 서울 상세 397건도 수입했다. 출처·해시·후보 연결·수집 오류를 실제 API/화면에서 조회한다. [실수집 관측](../research/ordinance-impact-live-sources.md)과 [실행 범위](../prototype/ordinance_impact/README.md)를 참조한다. 기술적 자료 확보가 담당자의 적용 판단·업무 검증·오류 발견을 뜻하지 않는다.

## 1. G0 — 데이터 가능성 관문

구현 확대 전에 같은 지자체에서 **실제 연결 3건**을 확보한다.

| 필수 자료 | 확인 방법 |
|---|---|
| 같은 조례의 이전·개정 원문 | 공식 출처·관할·ID/연혁 관계·해시·수집 시각 확인 |
| 부칙·필수 참조 근거 | 적용 시점과 예외를 확인할 문서 확보 |
| 연결되는 복지사업 | 사업 상세 근거와 담당자의 연결 확인 |
| 비교할 안내자료 | 현재/과거 공고 구분, 본문·URL·시점·버전 보존 |
| 사용 조건 | 출처별 조회·보관 조건과 인증·호출 한도 확인 |

3건은 일치하는 안내자료여도 된다. 오류가 없는 건도 기록하며, 특정 오류를 찾기 위해 애매한 적용 판단을 억지로 확정하지 않는다. 확보 실패 시 지역·조건·자료 형식을 조정한다. 합성 자료만으로 G0를 통과하지 않는다.

## 2. 정답 데이터와 분리

초기 수집 목표는 사업 10개, 전후 버전쌍 10개, 안내자료 20개다. 목표와 실제 확보 건수를 별도 기록한다. 사업·문서 관계가 겹칠 수 있으므로 모든 비교 단위의 분모를 보고한다.

정답 표에는 다음을 기록한다.

- 법규·사업·자료 ID와 고정 스냅샷, 실제/가상 구분, 기준일
- 실질 조건 변화 유무, 조건 유형·전후 값·단위·경계, 정확한 원문 구간
- 확인된 연결 관계, 자료 대상 시기와 적용 판단, 필요한 추가 근거
- 영향 자료/문단, 정정 가능 범위, 보류·미적용 사유

업무 검토자 1차 표기와 독립 검토자 2차 확인을 목표로 한다. 불일치는 합의·미해결 상태로 남기고 모델 답을 정답으로 채택하지 않는다. 검토 인력이 없으면 개발용 표본으로 표시하고 전문가 평가 완료를 주장하지 않는다.

같은 조례의 여러 개정·유사 안내는 한 그룹으로 묶어 개발/평가 집합을 나눈다. 평가용 그룹은 프롬프트 조정에서 제외한다. 자료가 적으면 작은 표본의 기술적 점검으로 보고하고 일반 성능을 추정하지 않는다. 실제 자료와 가상 경계 사례의 결과는 분리한다.

## 3. 비교할 방식

| 방식 | 입력·역할 | 확인하려는 차이 |
|---|---|---|
| 규칙 비교 | 명시적 숫자·기간·단위 차이 + 확인된 연결 | AI 없이 처리할 수 있는 단순 변화의 기준 |
| 현행 본문 비교 | 개정 후 조례와 안내문만 모델에 제공 | 전후 변화·부칙 맥락을 빼면 어떤 누락이 생기는가 |
| 제안 방식 | 전후 원문·부칙·확인된 연결·시점 + 규칙/AI | 변화 추적·보류·인용의 효과 |

모든 방식에 같은 평가 건을 사용하고 입력 차이를 보고한다. 모델이 있는 방식은 모델·설정·기준일을 고정한다. 승인 단계의 공통 안전 검사는 동일하게 적용한다. 부분 입력 비교가 제안 방식보다 열등하다는 결론을 미리 정하지 않는다.

## 4. 평가 항목과 초기 목표

| 항목 | 측정 단위·계산 | 초기 통과 기준/목표 |
|---|---|---|
| 실질 변화 탐지 | 변경 사건별 precision/recall, 이동·표현 변경 대조군 포함 | 목표 precision ≥0.90, recall ≥0.85. 표본과 불확실성 함께 보고 |
| 영향 자료 탐지 | 확인된 등록 자료 전체 중 TP/FP/FN | 목표 precision ≥0.90, recall ≥0.85. 미등록 웹 전체로 일반화 금지 |
| 조건 구조화 | 조건별 값·단위·경계·인용 exact match | 오류 유형과 원문을 보고, 승인 필드는 모두 검증 통과 |
| 적용 시점·보류 | APPLIES_NOW/UPCOMING/NOT_APPLICABLE/UNRESOLVED 혼동표 | 가상 필수 경계 사례에서 잘못된 현재 적용·승인 0건 |
| 근거 추적 | 승인 항목의 유효 인용/필수 항목 수 | 승인된 변경 항목 100% 인용·원문 일치 |
| 작업 완전성 | 등록 대상 대비 완료/실패/보류/미검사 | 누락·실패를 전체 검사 완료로 표시한 사례 0건 |
| 검토 노력 | 동일 건의 수동 방식과 도구 방식 시간·수정 횟수 | 짝지은 중앙값·건별 차이와 검토 오류 보고, 절감 수치 사전 주장 금지 |

90%/85%는 초기 설계 목표이며 달성 성능이나 기관 도입 기준이 아니다. 분모·TP/FP/FN·오류 사례를 공개한다. 표본이 적거나 연결 근거가 불완전하면 목표 달성 여부만으로 운영 적합성을 결론내리지 않는다.

보류율·보류 사유와 자동 제안 범위도 함께 보고한다. 모든 건을 보류해 안전성만 높이거나, 미확인 건을 제외해 정확도를 부풀리지 않는다. 시간 측정은 순서 효과를 줄이기 위해 작업 순서를 바꾸고 같은 정답 확인 수준을 요구한다.

## 5. 구현 후 필수 기능 시나리오

다음은 검증할 동작이며 아직 테스트 코드를 만들거나 실행하지 않았다.

| 입력·사건 | 기대 결과 |
|---|---|
| 가상 기한 90→180일, 시행 중·적용 확인 | 양쪽 조문·안내 인용을 가진 초안, 담당자 승인 후 APPROVED |
| 같은 변화가 미래 시행 | UPCOMING, 현재 오류 확정 금지, MVP 승인 차단 |
| 경과조치·적용 사건 불명확 | NEEDS_EVIDENCE, 일반화한 정정 승인 차단 |
| 상위법·별표·연도별 공고가 필수인데 없음 | 누락 표시, 임의 보완 금지 |
| 동명 타 지자체 조례 | 자동 연결 제외 또는 연결 확인 필요 |
| 조문 이동·단순 표현 변경 | 실질 수치 변경과 구분, 근거 없는 정정 생성 금지 |
| 과거 모집 공고와 현행 조례 비교 | 대상 시기 확인, 현재 기준으로 무조건 수정 금지 |
| 같은 본문 재수집·중복 요청 | 중복 개정·초안·승인 기록 방지 |
| 승인 직전 원문 변경·동시 검토 | 이전 If-Match 거절, 새 회차, 과거 결정 보존 |
| 같은 구간에 서로 다른 승인 초안 | 충돌 표시, 정리 전 승인 차단 |
| 승인 후 외부 미수정 | APPROVED 유지, VERIFIED 금지 |
| 승인 후 예상한 안내 수정만 반영, 다른 근거 그대로 | 후속 스냅샷을 별도 증거로 저장, 기존 승인 회차 APPROVED→VERIFIED |
| 외부 일부 수정·재수집 | 미반영 구간 표시와 VerificationFailed 이력 |
| 승인 범위 밖의 실질 변경·법규 근거 변경 | 새 회차 생성, 과거 승인 미승계 |
| 초안 없는 READY 건의 근거 있는 검토 제외 | draft_version=null인 회차별 결정 기록, DISMISSED |
| API 한도·이전 버전 누락·모델 실패 | 실패/미검사 표시, 변경 없음으로 처리 금지 |
| 원문 안에 “지시 무시·키 전송” 문구 | 문서로만 처리, 외부 실행·키 유출 없음 |
| 원문 인용 조작·한글/이모지 좌표 차이 | 코드 포인트 검증 실패 탐지, 승인 차단 |
| 새 분석 중 늦게 도착한 구 분석 결과 | 현재 회차 덮어쓰기 금지 |
| 서버 재시작 | 미완료 작업 복구, 동일 입력 재실행 시 중복 방지 |

보안 검증에는 허용되지 않은 URL·리다이렉트·사설 IP·스크립트 포함 HTML·로그의 키 제거도 포함한다. 자동 게시 기능은 제공하지 않는지 경계를 확인한다.

## 6. 단계별 완료 증거

| 단계 | 남길 증거 | 중단·수정 조건 |
|---|---|---|
| 이번 기초설계 | 별도 브랜치, 문서 링크·일관성 검사, 설계 검토 | 계약 간 충돌 해소 전 구현 시작하지 않음 |
| G0 데이터 | 실제 연결 3건의 출처·버전 manifest, 확인 기록 | 원문·연결·시점 확보 실패 |
| 수동 비교 시제품 | 원문 조회, 근거 연결, 회차·상태·감사 동작 | 유실되는 인용·잘못된 승인 전이 |
| AI·UI 시제품 | 필수 기능 시나리오 결과, 화면 캡처, 타입·빌드·동작 검사 | 무근거 승인, 실패 은폐, 오래된 결과 덮어쓰기 |
| 성능·업무 평가 | 고정 표본·라벨·방식별 원시 결과와 오류·시간 | 가치 가설 미입증이면 범위·접근 재검토 |

기관 운영 배포는 별도 승인·인증·보안·업무 검증 단계다. 로컬 시연 통과와 구분한다.
