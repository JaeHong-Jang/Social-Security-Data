# 공모전 수상작·실제 도구의 웹 프로토타입/대시보드 분석

- 작성일: 2026-11-13
- 목적: 「2026 사회보장 데이터를 활용한 AI 혁신 아이디어 경진대회」 출품용 웹 프로토타입(상담 안내 종결 위기가구 재검토 도구)의 화면·기능 결정 근거 확보
- 표기 규칙: 모든 사실 주장에 URL을 단다. 확인하지 못한 내용은 **미확인**으로 적는다. "검색 요약 기준"은 원문 페이지가 차단(403)되거나 PDF를 열지 못해 검색엔진 요약으로만 확인한 경우다.

## 0. 핵심 결론 (먼저 읽을 것)

1. **이 대회에는 참고할 '과거 수상작'이 사실상 없다.** 이번 대회는 2026년 공고(접수 10.21~11.20, 본선 발표·시상 12.3)이고, 2025년판은 검색되지 않았다(미확인). 제출물은 HWP 아이디어 제안서이며 시제품·영상 요건은 공고에 없다. 따라서 웹 프로토타입은 ① 제안서 속 화면 캡처, ② 본선 발표 시연 두 용도로 쓰인다. ([링커리어 공고](https://linkareer.com/activity/360109))
2. **국내 데이터·AI 공모전 수상작의 화면은 '지도 + KPI 카드 + 진단·분석·처방 3단 + AI 챗봇 버튼' 조합이 반복된다.** 2026 서울시 빅데이터 활용 경진대회 시각화 부문 대상과 최우수, 수상 여부가 확인되지 않은 공개 프로젝트(SHADOW-AI)가 모두 이 구조다. 우리가 이 틀을 따르면 흔해 보인다.
3. **사회보장정보원·복지부가 이미 비슷한 기능을 로드맵에 올려 두었다.** 모바일 행복이음에 '위기가구 예측 강화, 복지상담 분석·요약, 복지서비스 추천'을 순차 적용할 예정이고([헤럴드 2026-04-29](https://www.heraldk.com/article/2026042917402456575)), 경기도 5개 시는 '음성 자동 기록 + 실시간 서비스 추천' 업무지원 AI를 2026년 8월부터 실증한다([세계일보 2026-07-29](https://www.segye.com/newsView/20260729518867)). 그래서 F1(메모 요약)이나 F3(서비스 추천)만으로는 차별화가 안 된다. 차별점은 **'상담 안내로 종결된 사람을 다시 꺼내는 재검토 흐름'과 '근거 인용·사람 결정·감사 기록'** 쪽에 둬야 한다.
4. **'AI 판단 근거'를 보여주는 방식은 해외 연구에서 답이 거의 나와 있다.** 아동복지 선별 담당자 대상 연구(Sibyl)에서 **사례별 요인 기여도** 화면은 전문가 사례의 91.8%에서 도움이 됐다고 평가됐다. 반면 what-if 샌드박스는 16.4%, 전체 변수 중요도는 0%였고, 유사 사례 비교는 편향 우려로 아예 빠졌다([Sibyl 논문](https://ar5iv.arxiv.org/html/2103.02071)). AFST 현업자들은 "숫자만 준다"고 불만을 표했고 "상위 3개 요인만 알아도 도움이 된다"고 했다([Kawakami et al. CHI'22](https://ar5iv.labs.arxiv.org/html/2204.02310)).
5. **'사람이 최종 결정'은 문구가 아니라 화면 장치로 보여줘야 한다.** AFST는 기본값 넛지와 감독자 재정의를 두고 재정의 시 서면 사유를 요구하며, 점수는 선별 담당자와 감독자만 보고 조사 담당자에게는 보이지 않는다([Allegheny 2024](https://analytics.alleghenycounty.us/wp-content/uploads/2024/05/24-ACDHS-04-Predictive-Risk-Algorithms.pdf), [AFST FAQ](https://analytics.alleghenycounty.us/wp-content/uploads/2019/05/FAQs-from-16-ACDHS-26_PredictiveRisk_Package_050119_FINAL-8.pdf)). 국내 AI 기본법 제34조도 고영향 AI에 ①설명 방안 ②사람의 관리·감독 ③문서 작성·보관을 요구하고, 제2조제4호자목은 공공서비스 자격 확인·결정을 고영향 영역으로 명시한다([국가법령 영문/국문](https://elaw.klri.re.kr/kor_service/lawViewMultiContent.do?hseq=71019)). 이 조항을 화면 요소와 1:1로 대응시키면 심사위원에게 설득력이 크다.
6. **추천 화면은 4개다.** ①재검토 대기열 ②가구 상세(메모 근거·점수 분해·타임라인·결정 패널) ③맞춤 재안내(서비스 후보 3개·원문 조건·쉬운 말 안내문) ④감사 로그·성과. 지도, 대형 KPI 벽, 상시 챗봇, what-if, 유사 사례, 성별·연령 표시는 뺀다. 자세한 구성은 4장에 있다.

## 1. 조사 범위·방법·한계

- 한국어·영어 웹 검색, 기관 공고·보도자료, GitHub 검색 API, 공개 발표자료 PDF(이미지 추출 후 직접 확인), 학술 논문(arXiv/ar5iv)을 활용했다.
- **한계 1: 국내 공모전 보도에는 화면 설명이 거의 없다.** 국민행복 서비스 발굴·창업경진대회(2024~2026), 행안부 공공 AI 대전환 챌린지(2025) 기사는 아이디어 한 줄만 싣고 화면·심사평은 없었다. 화면을 직접 확인할 수 있었던 국내 수상작은 발표자료가 공개된 **2026 서울시 빅데이터 활용 경진대회 시각화 부문**과 GitHub README에 스크린샷이 있는 몇 건뿐이다.
- **한계 2: 접근 실패 목록.** local.gov.uk(Kingston 사례, 403), socitm.net(Swindon, 403), swindon.gov.uk(본문 비어 있음), wikidocs(403), KIHASA 2025.09 PDF(로딩 실패). 이 출처들은 검색 요약 수준으로만 인용했다.
- **한계 3: '심사위원이 왜 뽑았는가'는 거의 공개되지 않는다.** 아래 사례에서 수상 사유는 별도 표기가 없으면 미확인이다. 추론으로 적은 부분은 "(추론)"이라고 표시했다.

### 2-2. 사례 상세

**A1. 2026 서울시 빅데이터 활용 경진대회 시각화 부문 대상 「혼자 사는 서울, 함께 보는 서울」 (서울돋보기팀)**
- 출처: [수상작 페이지](https://data.seoul.go.kr/bsp/wgs/contest26.do), [발표자료 PDF](https://data.seoul.go.kr/bsp/images/contest26/seoul-lens.pdf), [라이브 데모](https://web-lime-nine-77.vercel.app/)
- 주제가 "1인가구 안전 지표"라서 위기가구를 다루는 우리 주제와 가장 가깝다. 수상작 페이지 설명은 "서울 1인 가구의 안전 지표를 공간과 생활 유형별로 탐색"이다.
- 화면 구성(발표자료 PDF에서 이미지를 추출해 직접 확인):
  - 상단 6단계 내비게이션: 01 한밤의 서울 / 02 귀가 위험 / 03 고독 위험 / 04 응급 위험 / 05 시뮬레이터 / 06 보고서. 키보드 ←→로 넘긴다.
  - 히어로 화면: "163만 가구 · 서울 전체의 36%" 같은 큰 숫자와 지도 배경.
  - 위험 탭: 가운데 자치구 지도, 왼쪽 내러티브 패널(핵심 수치 3개와 출처 코드 "서울 데이터 허브 OA-14991…"), 오른쪽 **페르소나 카드**("지원, 27세·여성·관악구 … 새벽 1:20, 위험지수 88")와 '혼자이기 때문에' 설명 박스, 하단 분석 레이어 토글(CCTV 부족, 가로등 부족 등).
  - 시뮬레이터: 자치구를 클릭하고 정책 슬라이더(CCTV·가로등·생활관리사 추가)를 움직이면 개선 효과(%)와 추정 예산("약 2.9억원")이 바로 계산된다.
  - 보고서: 위험 유형별 KPI 카드 3장(귀가 약 28만, 고독 약 19만, 응급 약 14만), 각 카드에 데이터셋 코드, 상단에 "모든 수치에 '추정' 조건이 적용됩니다" 문구.
  - 화면 오른쪽 아래 상시 'AI 큐레이터' 챗 버튼.
- 수상 사유: 공개된 심사평이 없어 미확인. (추론) 스토리텔링 완성도, 정책 시뮬레이터의 '처방' 연결, 출처와 추정을 표기한 정직성이 강점으로 보인다.
- 우리에게 주는 시사점: **출처 코드와 '추정' 표기 관행은 가져오되,** 지도·페르소나·대형 숫자 중심의 '도시 전체를 보는 정책가용' 화면은 우리 사용자(읍면동 담당자 1명이 오늘 처리할 가구 목록)와 맞지 않는다.

**A2. 같은 대회 최우수 「서울시 자치구별 쓰레기 발생 구조 진단 대시보드」**
- 출처: [수상작 페이지](https://data.seoul.go.kr/bsp/wgs/contest26.do), [대시보드](https://data.seoul.go.kr/bsp/contest26/visualizations/trash/index.html)
- 확인된 구조는 "CH.1 진단 / CH.2 분석 / CH.3 처방" 3단 장 구성뿐이고, 세부 컴포넌트는 미확인이다. '진단→분석(예측)→처방' 3단 서사는 A1과 SHADOW-AI에서도 반복된다.

**A3. 2025 서울 데이터 허브 시각화 경진대회**
- 출처: [수상작 페이지](https://data.seoul.go.kr/bsp/wgs/contest26.do)(2025 목록이 같은 페이지에 있다)
- 대상 「걸어서 15분, 문화에 닿는 서울」(보행 네트워크 기반 문화 접근성), 우수 「서울의 이면」(마음건강·자살·우울 통계를 연령·성별·지역별로 시각화하고 심리지원 채널과 연결) 등. 데모 링크는 없고 발표자료만 공개됐다.
- 시사점: 복지 성격의 수상작도 결과물은 **지역 단위 시각화와 정책 제안**이다. '개별 사례를 처리하는 업무 화면'은 수상작 중 찾지 못했다(본 조사 표본 기준).

- 대상: 복지 사각지대에 있는 시민. 화면 5종은 추천 복지 열람, 챗봇(KcELECTRA 일상대화 + KoSBERT 복지정보), 복지시설 안내, 실시간 푸시 알림, 관심복지 저장이다. 공공데이터포털 복지 데이터를 임베딩해 썼고 Play Store에 정식 출시했다가 현재는 서비스를 중지했다.
- 수상 사유: 미확인. (추론) 실제 출시와 실동작 시연이 강점이었을 것이다.
- 시사점: '시민용 복지 추천 + 챗봇'은 2021년에 이미 대상을 받은 유형이다. 2026년에 같은 축으로 가면 새로움이 약하다.

**A5. 2022 사회가치창출 아이디어 공모전 대상 「어울림」 (팀 mypd)**
- 출처: [서울신문 2022-12-14](https://m.seoul.co.kr/news/2022/12/14/20221214019056)
- 마이데이터로 복지서비스 자격을 확인하고, 요건을 충족하면 필요 서류를 자동으로 준비해 원클릭 신청까지 잇는다. 85팀 중 12팀이 수상했다. 심사 사유는 기사에 없다(미확인).
- 시사점: '자격 판정과 신청 자동화'도 시민용 흐름으로 이미 다뤄졌다. 우리 F3은 **자격을 판정하지 않고 원문 조건과 대조 근거만 보여주는 담당자 보조**로 선을 그어야 차별화되고 위험도 낮다.

**A6. 2023 청소년상담복지사업 국민 아이디어 공모전 대상 「YouAreNotAlone」**
- 출처: [GitHub README](https://github.com/ARIARI-AIVLE/YouAreNotAlone) (수상 내역은 README 자기 기재)
- Kaplan의 1·2·3차 예방 틀에 맞춰 2차 예방에는 CatBoost와 SHAP으로 가해 위험 청소년을 분류하고 중요 특성을 추출했다. 3차 예방에는 Streamlit과 AWS EC2로 상담 챗봇 웹을 만들었다.
- 시사점: 수상작에서도 **SHAP 등 '근거 분해'**를 넣는 흐름이 보인다. 다만 이 작품은 분석 결과물이고 업무 화면은 아니다.

**A7. 국민행복 서비스 발굴·창업경진대회 (사회보장정보원 주관)**
- 2026 대상: Atmos팀 「소리블록」. 사회보장·공공시설 데이터 기반 이동약자용 AI 실내 내비게이션이다. "가장 가까운 장애인 화장실로 안내해줘" 같은 음성 요청을 받는다. 249팀 중 27팀이 수상했고 대상은 복지부장관상과 700만원이다. ([디지털데일리](https://m.ddaily.co.kr/page/view/2026072313553789658))

- 2024 장려상: GIST·전남대 '어시스트'의 발달장애인 길찾기 앱(보호자 위치 공유, 위험 감지). ([대학저널](https://www.dhnews.co.kr/news/view/1065572428316266))

- 시사점: 같은 기관이 주관한 창업대회 수상작은 **시민용 앱**이 주류다. 공무원 업무 도구는 상대적으로 드물어서 그 자체로 포지셔닝 기회다(본 조사 표본 기준, 추론).

**A8. 2026 고용노동부 제5회 공공데이터·AI 활용 공모전 (우수작 14개, 총상금 1,800만원)**

**A9. 2025 행안부 공공 AI 대전환 챌린지 결선 (2025-12-03, 15팀)**

### 2-3. 비교용 공개 프로젝트 (수상 미확인)

- **SHADOW-AI** ([GitHub](https://github.com/suky8658/Oracle-Shadow-AI-seoul)): 서울 5060 남성 1인가구 고립을 다룬 "복지 의사결정 지원 대시보드"다. 구조는 SHADOW Map(진단·4분면), SHADOW AI(행정동 전이 예측·SHAP), SHADOW RAG(처방, LLM은 "근거 안에서만" 작성), 담당자 질의응답 챗봇이다. 수상 여부는 미확인이다. **지역 단위, 진단·예측·처방, SHAP, RAG 챗봇**이 한 프로젝트에 모두 들어 있는 전형적인 예다.

## 3. 실제 운영 중인 유사 도구

### 3-1. 국내

**B1. AI 초기상담 (복지부·사회보장정보원, 2024~)**
- 2024-07-22부터 4차 사각지대 발굴에서 101개 시군구 위기가구를 대상으로 AI 전화 초기상담 시범을 했고, 이후 전국 확대를 계획했다. 문자로 먼저 알리고 1600-2129(발신 전용)로 전화한다. **상담 내용은 시스템을 통해 지자체 공무원에게 자동 제공되어** 심층상담·가구방문 자료로 쓰인다. ([강남구 안내](https://www.gangnam.go.kr/board/B_000031/1073831/view.do?mid=ID01), [광명시 기사](https://news.tf.co.kr/read/ogmeta/2118306.htm))
- 강남구 안내에 나온 대화 흐름은 통화 연결 → 인사·본인 확인 → **위기 상황 파악 → 욕구 파악** → 후속 상담 안내·종료다. 결과는 복지행정망(행복이음)에서 조회한다. 전국 확대 완료 여부와 담당자 화면 구성은 미확인이다.
- 시사점: 담당자는 이미 'AI가 만든 상담 결과'를 받고 있다. 우리 F1이 다루는 '과거 상담 메모'와 데이터 형태가 이어지므로, 시연에서 "기존 초기상담·상담 기록을 재활용한다"고 말할 수 있다(추론).

**B2. 모바일 행복이음 (2026-04 설명회)**
- 현장에서 대상자 조회, 상담 기록 등록, 요금 감면 신청을 즉시 처리하는 '현장 완결형'으로 바뀌고 있다. 향후 AI 서비스로 **①위기가구 예측 강화 ②복지상담 분석·요약 ③복지서비스 추천**을 모바일에 순차 적용할 계획이다. ([헤럴드 2026-04-29](https://www.heraldk.com/article/2026042917402456575))
- 시사점: 기관 로드맵과 우리 F1·F3이 겹친다. 경쟁하지 말고 **"행복이음에 붙는 재검토 모듈"**로 포지셔닝하는 편이 낫다(추론).

**B3. 경기도 5개 시 '복지행정 AI 정책실험실' 실증 (2026-08~연말, 국비 1억6,800만원)**
- 수원·화성·평택·시흥·오산이 참여하고, 복지부·사회보장정보원과 2026-07-29에 협약했다. 공무원용 '업무 지원 AI'는 가정방문·현장상담의 **음성 자동 텍스트 기록**과 **상담별 실시간 서비스 추천**을 한다. 국민용 'AI 복지 서비스'는 생성형 AI로 욕구를 파악하고 위험도를 분류한다. 화면과 사람의 검토 절차는 기사에 없다(미확인). ([세계일보](https://www.segye.com/newsView/20260729518867), [서울신문](https://m.go.seoul.co.kr/news/2026/07/29/20260729500033))

**B4. 서울시 AI 안부확인 / 네이버 클로바 케어콜**
- 서울시는 2022년 10월부터 고립위험가구에 AI가 전화로 안부를 묻고 결과를 동주민센터에 넘기는 방식을 운영한다. 2025년 11월부터는 18개 자치구 1,800명 대상으로 양방향(대상자가 AI에 전화) 시범을 한다. ([서울시 복지 누리집](https://news.seoul.go.kr/welfare/archives/574354), [미디어허브](https://mediahub.seoul.go.kr/archives/2013252))
- 클로바 케어콜은 통화 후 건강·식사·수면 등 핵심 항목을 요약·기록하고, 지자체 담당자가 후속 조치를 할 수 있도록 "모니터링 도구"를 제공한다(2022-08 보도자료). 화면 세부는 미확인이다. ([네이버 보도자료](https://navercorp.com/media/pressReleasesDetail?seq=30860))
- 시사점: 국내 담당자 도구는 'AI 결과를 담당자에게 넘기고 사람이 후속 조치'하는 구조가 표준이다. 우리 F4(사람 검토)는 현장 관행과 맞는다.

**B5. 인공지능기본법(2026-01-22 시행): 화면 설계의 법적 앵커**
- 제2조제4호자목: "공공서비스 제공에 필요한 자격 확인 및 결정 또는 비용징수 등 국민에게 영향을 미치는 국가, 지방자치단체, … 공공기관 등의 의사결정"을 고영향 AI 영역으로 명시한다.
- 제34조제1항: ①위험관리방안 ②"인공지능이 도출한 최종결과, … 주요 기준, … 학습용데이터의 개요 등에 대한 설명 방안" ③이용자 보호 방안 ④"고영향 인공지능에 대한 사람의 관리ㆍ감독" ⑤"안전성ㆍ신뢰성 확보를 위한 조치의 내용을 확인할 수 있는 문서의 작성과 보관".
- 출처: [한국법제연구원 영문/국문 법령](https://elaw.klri.re.kr/kor_service/lawViewMultiContent.do?hseq=71019)
- 우리 도구가 법적으로 고영향 AI에 해당하는지는 판단하지 않았다(미확인). 우리는 '자격 결정'을 하지 않고 '재검토 우선순위 제안'만 한다. 그래도 제34조 항목을 화면에 대응시키면 설계 의도를 설명하기 좋다(4장 표 참고).

### 3-2. 해외

**B6. Allegheny Family Screening Tool (AFST, 미국 펜실베이니아, 2016~)**
- 화면: 선별 담당자가 1~20 점수를 생성한다. 점수 18~20이고 16세 미만 아동이 있으면 숫자 대신 **"High-Risk Protocol"** 문구가 뜨고, 1~12이고 모든 아동이 7세 이상이면 **"Low-Risk Protocol"**이 뜬다. 각 프로토콜은 화면의 결정 기본값을 screen-in/out으로 설정하지만, 감독자는 이를 **재정의할 수 있고 실제로 자주 재정의한다**. ([Allegheny 2024 요약 보고서](https://analytics.alleghenycounty.us/wp-content/uploads/2024/05/24-ACDHS-04-Predictive-Risk-Algorithms.pdf))
- 재정의 시 서면 사유: 고위험 프로토콜을 기각하려면 "supporting documentation"이 필요하고, 재정의 기록은 문서화·검토된다. ([AFST FAQ 2019](https://analytics.alleghenycounty.us/wp-content/uploads/2019/05/FAQs-from-16-ACDHS-26_PredictiveRisk_Package_050119_FINAL-8.pdf))
- 점수 접근 제한: 점수는 선별 담당자와 감독자만 본다. 조사 단계 담당자와 법원은 볼 수 없다. 2024 보고서는 "neither the assigned investigator nor any caseworker ever sees the AFST score"라고 적었다. (같은 출처)
- 결과: 첫해에 '의무 screen-in' 점수의 63%만 실제로 screen-in됐다(FAQ). 기본값 넛지는 "only minimal additional concurrence"에 그쳤다(FAQ).
- 시각화 평가: 온도계형 점수 그래픽을 두고 의견을 낸 직원의 70%가 "제한적으로만 도움 또는 전혀 도움 안 됨"이라고 답했다. 검색 요약 기준이며 원문은 열람하지 못했다. ([Process Evaluation](https://www.alleghenycountyanalytics.us/wp-content/uploads/2019/05/Process-Evaluation-from-16-ACDHS-26_PredictiveRisk_Package_050119_FINAL-4.pdf))
- 카운티의 향후 과제: 재정의 상황에 맞춘 피드백 제공, **단일 점수 대신 여러 결과별 점수 제시** 검토. (2024 보고서)

**B7. AFST 현업자 연구 (Kawakami et al., CHI 2022)**
- 출처: [ar5iv](https://ar5iv.labs.arxiv.org/html/2204.02310)
- 현업자들은 숫자 점수나 의무 screen-in 메시지만 주는 화면에 불만이 있었다. "점수가 어떻게 나왔는지 더 알면 더 주의를 기울일 것"(C3), "점수에 영향을 준 상위 3개만 알아도"(C6)라고 말했다. 중간대 점수(약 10~14)는 숫자 외 정보가 없어 대체로 무시됐다.
- 원하는 것: 영향 요인, 반사실(이 항목을 빼면 점수가 어떻게 되나), 데이터 출처, **결정 정당화 지원**, "지시가 아니라 협업처럼 느껴지는" 표현, 피드백이 반영되는 "two-way street".

**B8. Sibyl (MIT·AUT, IEEE VIS 2021): 아동복지 선별용 설명 UI 사용성 연구**
- 출처: [ar5iv 전문](https://ar5iv.arxiv.org/html/2103.02071), [arXiv](https://arxiv.org/abs/2103.02071v2)
- 선별 담당자 인터뷰 19명, 비전문가 12명·전문가 13명 대상 사용자 연구를 했다.
- 화면별 "도움 됨" 평가:

| 화면 | 전문가 | 비전문가 | 비고 |
|---|---|---|---|
| 사례별 요인 기여도(SHAP) | **91.8%** | 90.7% | 위험 요인과 보호 요인을 나눠 보여 달라는 요청을 받아 기본 상위 10개만 표시 |
| Sandbox(what-if) | 16.4% | 22.6% | 인과·조치 암시 우려, 교육·감독용으로는 가치 있음 |
| 요인 분포 | 20.5% | 8.0% | 교육·서비스 공백 파악용 |
| 전체 변수 중요도 | 0% | 0% | 실시간 판단에는 과함 |
| 유사 사례 | (연구에서 제외) | — | 대표성 편향·자기실현 우려 |

- 설계 함의: 표시 요인 수를 제한한다, 상관된 요인은 합친다, "위험/보호" 같은 **평이하고 긍정형 문장**을 쓴다("CHILD DOES NOT HAVE SIBLINGS"처럼 true/false 대신 문장으로), 정렬 순서가 만드는 가용성 편향에 주의한다. 담당자가 사례당 몇 분밖에 쓰지 못하므로 상세 뷰는 교육·감독용으로 돌린다.
- 신뢰: 비전문가는 46.4% 사례에서 모델에 "많이" 의존했고 전문가는 15.6%였다. 핵심 요인이 무시된 것 같을 때 전문가의 신뢰가 떨어졌다.

**B9. Magic Notes (Beam, 영국 지자체 사회복지)**
- 작동: 상담·회의를 녹음하면 전사본, 요약, 후속 조치 제안을 만들고, 지자체와 합의한 프롬프트에 맞춰 사례기록 형식으로 만든다. **담당자가 검토한 뒤에야 사례관리시스템에 넣는다.** 검색 요약 기준이며 원문은 403이었다. ([LGA Kingston 사례](https://www.local.gov.uk/case-studies/kingston-council-using-ai-adult-social-care-administration))
- 성과: Somerset 아동사회복지 파일럿(20명)에서 행정 시간이 주 46% 줄고 평가·보고서 제출이 65% 빨라졌으며, 95%가 계속 사용을 원했다. "a human being will always be involved." ([Somerset](https://www.somerset.gov.uk/news/somerset-social-workers-save-time-on-admin-thanks-to-ai-tool-magic-notes/)) Kingston은 파일럿에서 행정 시간이 63% 줄었고 성인사회복지 100명으로 확대했다. ([Kingston](https://www.kingston.gov.uk/news/2024/kingston-council-launches-ai-tool-free-time-frontline-social-workers))
- 우려: 영국 사회복지사협회(BASW)와 노조는 윤리 문제에 대한 정부 조치와 대상자 동의 명확화를 요구했다. 검색 요약 기준. ([Community Care](https://www.communitycare.co.uk/?p=212114))
- 시사점: **'AI 초안 → 담당자 검토·수정 → 시스템 반영'** 3단계가 현장에서 받아들여진 표준이다. 우리 F1 추출 결과도 '확정 전 초안' 상태로 보여야 한다.

**B10. Bristol Think Family Database (영국)**
- NEET 위험 모델: 담당자는 Children & Families View에서 점수를 본다. 사람별 설명 문구가 **왜 표시됐는지**와 **이전 점수 대비 추세(상승·하락·과거·정체)**를 알려준다. "not used to make decisions"이고, 출력은 무작위로 추적·감사하며 6개월마다 재검토한다. 70개 이상의 다른 취약성 지표와 함께 보도록 안내한다. ([gov.uk 알고리즘 투명성 기록](https://gov.uk/algorithmic-transparency-records/bristol-city-council-not-in-education-employment-or-training-model))
- 실패 사례: 아동 성착취·범죄착취 위험 모델은 피해자보다 절도 연루자 점수가 높게 나오는 등 오분류가 있었고, 2023년 "not fit for operational use"로 종료됐다. 직원들은 점수 산출 방식을 몰라 "회의에서 인용할 자신이 없다"고 했다. 아동위원장은 "transparent"해야 한다고 촉구했다. ([Bristol Cable 2026-06](https://thebristolcable.org/2026/06/bristol-data-tools-risked-wrongly-flagging-victims-and-suspects-childrens-commissioner-deeply-concerned/))
- 시사점: **추세 표시(지난번 대비 변화)**와 **사유 문장**은 가져온다. 점수 산출 근거를 숨기면 현업이 쓰지 않는다는 반면교사도 된다.

**B11. Rotterdam 복지 부정수급 위험 모델 (네덜란드)**

**B12. Salesforce Public Sector Solutions (사례관리 표준 UI 참고)**

### 4-3. (c) 추천 화면 구성 (4개)

공통 원칙
- 사용자는 읍면동 맞춤형복지 담당자 1명이고, 하루 단위로 업무를 처리한다.
- 모든 화면 상단에 "가상 데이터 시연" 배너를 둔다. 성별·연령은 화면 어디에도 표시하지 않는다.
- LLM 출력은 항상 '초안' 상태로 표시하고, 사람이 확정해야 다음 단계로 넘어간다.

**화면 1. 재검토 대기열 (홈)**
- 목적: "오늘 누구부터 다시 볼지"를 정한다.
- 구성요소
  1. 작은 요약 줄 3개: 재검토 대기 N건 / 이번 주 처리 M건 / 동의 확인 필요 K건. 대형 카드가 아니라 한 줄 텍스트다.
  2. 목록(테이블): 가명 가구 ID, 상담 안내 종결일과 경과일, 재검토 점수(가로 막대 + **상위 사유 2개 칩**, 예: "종결 후 단전 정보 재입수 +15", "메모: 본인 도움 원함 +10"), 동의 상태 배지(동의/거부/미확인), F1 추출 상태(AI 초안/확정), 처리 상태(미검토·검토중·완료).
  3. 필터: 경과 기간, 사유 유형, 동의 상태, 처리 상태. 정렬 기본값은 점수, 경과일로도 바꿀 수 있다.
  4. "정렬 기준 보기" 링크: 100점 규칙 요약 팝오버(항목·배점·"성별·연령 미사용").
- 뺄 것: 지도, 위험 등급 색 경보 배너, 챗봇, 자동 일괄 배정.
- 근거: Kawakami(상위 요인 표시), Sibyl(요인 수 제한), Salesforce(대기열 → 사례), AFST(점수는 내부 업무용).

**화면 2. 가구 상세 (핵심 시연 화면)**
- 목적: AI 근거를 확인하고 사람이 결정한다.
- 레이아웃 제안: 3열 + 하단
  1. 왼쪽: **과거 상담 메모 원문**. F1이 근거로 쓴 구간을 하이라이트하고, 오른쪽 카드와 서로 이동 링크로 연결한다.
  2. 가운데: **F1 추출 카드**. 상태 항목(예: 소득 단절, 건강 악화, 주거 위기)과 동의 여부를 보여준다. 항목마다 근거 인용문, '확인 필요' 플래그(인용이 없거나 모호할 때), 담당자의 수정·확정 버튼이 있다.
  3. 오른쪽: **F2 점수 분해**. 100점 누적 막대, 항목별 가점과 한 줄 사유, 데이터 출처, "사용하지 않는 정보: 성별·연령" 문구를 둔다. 위험 요인과 완화 요인을 분리할 수 있으면 분리한다(Sibyl).
  4. 하단: **타임라인**. 최초 발굴 → 상담 안내 종결 → 종결 이후 새 위기정보·연락 이력 → 재검토(현재) 순서이고, 종결 이후 변화를 강조한다(Bristol 추세 표시).
  5. 결정 패널(오른쪽 고정): 재안내 / 방문 상담 / 보류(재검토일 지정) / 종결 유지. AI 제안과 다르게 고르면 **사유 입력이 필수**이고, 저장하면 감사 로그로 간다.
- 뺄 것: what-if 슬라이더, 유사 사례, 전체 변수 중요도, 게이지형 점수, 챗봇.
- 근거: Sibyl·Kawakami(요인 기여도), Magic Notes(초안 → 검토), AFST(재정의 + 사유), AI 기본법 제34조 2·4호.

**화면 3. 맞춤 재안내**
- 목적: 서비스 후보를 확인하고, 대상자에게 보낼 안내문 초안을 만든다.
- 구성요소
  1. 서비스 후보 카드 **최대 3개**. 서비스명과 소관 기관, **선정기준 원문 인용**(복지서비스 API 원문 그대로), 원문 조건과 가구 정보 대조표(충족/미충족/확인 필요, 각 판단의 근거 출처), API 출처와 조회 일시를 넣는다. "자격 판정 아님, 담당자 확인 필요" 문구도 붙인다.
  2. 쉬운 말 안내문 편집기. 왼쪽에 원문 조건, 오른쪽에 쉬운 말 초안을 나란히 두고, 담당자가 직접 수정한다. 점수와 위험 사유는 안내문에 자동으로 넣지 않는다.
  3. 발송 전 확인 체크리스트: 동의 상태, 개인정보 노출 여부, 문장 확인. 체크가 끝나야 '승인' 버튼이 켜진다(자동 발송 없음).
- 뺄 것: 자동 발송, 원클릭 신청(A5와 겹치고 범위 밖), 대상자에게 점수 노출.
- 근거: A8 「내 권리 지키미」(원문 근거), A1(출처 표기), AFST(점수 비공개 범위), A5와의 차별화.

**화면 4. 감사 로그 · 성과**
- 목적: "사람이 결정했고 기록이 남는다"를 증명하고, 운영 효과를 보여준다.
- 구성요소
  1. 감사 로그 테이블: 시각, 담당자, 대상 ID, 행위(추출 확정·점수 확인·결정·안내문 승인), AI 제안, 최종 결정, 사유, 규칙/프롬프트 버전. 필터와 CSV 내보내기를 둔다.
  2. 성과 요약(작게): 재검토 처리 건수, 재연계 건수와 비율, 평균 처리 시간, **AI 제안과 담당자 결정 일치율과 불일치 사유 분포**(양방향 피드백 루프).
  3. (선택) 규칙 변경 이력: 배점 버전과 변경 사유.
- 뺄 것: 지도 관제, 실시간 알림 피드, 성별·연령별 집계 차트.
- 근거: AI 기본법 제34조 5호, AFST의 재정의 기록과 피드백 계획, Bristol의 무작위 감사.
- 팀 결정 필요(트레이드오프): 점수에는 성별·연령을 쓰지 않지만, **사후 공정성 점검용으로 집계할지**는 별개 문제다. 집계하면 편향을 점검할 수 있지만 민감정보를 처리하게 되고, 집계하지 않으면 편향을 검증할 수 없다. 시연용 가상 데이터에서 어느 쪽을 택할지 정해야 한다.

### 4-4. 시연·제안서 운용 팁

- 제안서가 HWP이므로 **화면 캡처 4장 + 화면별 한 줄 설명 + 위 법 조항 대응표**를 넣는 구성을 추천한다(추론).
- 본선 발표(12.3)에서는 가구 1건을 끝까지 따라가는 3분 시나리오가 좋다. 대기열에서 선택 → 메모 근거 확인 → 점수 분해 → AI 제안과 다른 결정 + 사유 → 안내문 승인 → 감사 로그 순서다. 지도나 챗봇 대신 이 '결정 장면'을 보여주는 것이 흔한 대시보드와의 차별점이다(추론).
- 국가 로드맵(모바일 행복이음의 상담 분석·요약·서비스 추천)과 겹친다는 지적이 나오면 "행복이음에 붙는 재검토 모듈"이라고 답한다(추론).
