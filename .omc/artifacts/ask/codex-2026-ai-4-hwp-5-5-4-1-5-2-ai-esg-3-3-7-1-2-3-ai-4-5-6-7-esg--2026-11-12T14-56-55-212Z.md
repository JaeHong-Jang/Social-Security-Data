- RAG는 공개 API에서 확인한 지원 정보를 검색하여 상황에 맞는 후보 2~3개와 쉬운 말 안내문을 생성하되, 정보가 부족한 경우 추가 확인 사항을 표시함.
- 프로토타입에서는 LLM의 비정형 기록 해석·문장 생성과 규칙 기반 점수 계산을 결합하며, 분류 성능·추천 근거 일치·검토 소요시간을 평가하여 개선효과를 제시할 예정임.

## 3. ‘사회보장 데이터 활용’ 25점 대응 체크리스트

핵심 입증사항은 **어떤 데이터가 어떤 판단에 사용되어 담당자의 후속 조치를 바꾸는지**임.

- [ ] **공개 API 실연동 증거:** 실제 요청·응답, 조회 시점, 사용한 데이터 항목을 제시함. 캐시를 사용한 경우 저장 시점을 표시함.
- [ ] **데이터별 사용 목적:** 각 데이터가 분류·우선순위·지원 검색 중 어디에 활용되는지 데이터 사전과 화면에서 확인할 수 있음.
- [ ] **원천까지 추적 가능한 출력:** 지원 후보와 안내문에서 사용한 API 항목·서비스 식별정보·출처를 확인할 수 있음.
- [ ] **반복 발굴 이력 연결:** 동일한 가상 가구의 3월·7월 기록이 연결되며, 과거 기록을 활용했을 때의 판단 차이를 보여줌.
- [ ] **종결 범주 세분화:** ‘조사 중’과 ‘종결’을 구분하고, 미응답 후 안내문 발송처럼 복수의 사유·조치를 보존함.
- [ ] **통계 반영 근거:** 가상 데이터 생성 규칙, 통계 출처, 모집단, 반영한 분포 및 시연을 위한 가정을 구분함. 연령·성별의 주변 분포만으로 결합 분포를 만들어 사실처럼 제시하지 않음.
- [ ] **점수 근거 공개:** 순위뿐 아니라 입력 이력·항목별 기여·산식·가중치를 보여줌. 검증 전 가중치는 설정값으로 표시하고 연령·성별만으로 우선순위를 결정하지 않음.
- [ ] **조건을 확인하는 RAG:** 지역·대상 조건 등 실제 확인 가능한 정보를 반영함. 정보가 부족하면 자격을 확정하지 않으며, 후보가 부족할 때 임의로 채우지 않음.
- [ ] **데이터 활용의 기여 비교:** 현재 기록만 사용한 경우와 과거 이력까지 사용한 경우를 비교하여 추가 데이터의 역할을 보여줌.
- [ ] **평가의 재현성:** 평가 사례·기준 답안·산식·오류 사례를 보관하고 정확도 등 결과를 실제 측정함. 같은 LLM의 자체 판정만으로 정답을 확정하지 않음.
- [ ] **현실 적용의 경계 명시:** 실제 공개 API와 가상 개인 이력을 화면에서 구분하고, 가상 데이터 평가 결과를 현장 성능으로 표현하지 않음.
- [ ] **후속 조치까지 연결:** 담당자의 분류 수정, 재접촉 판단, 안내문 검토 및 결과 기록이 저장됨. 안내문 생성이나 발송만으로 실제 지원 연계를 완료 처리하지 않음.

## 4. 심사위원 예상 질문 5개와 답변

**① “복지멤버십이나 AI 초기상담과 무엇이 다른가?”**

복지멤버십은 가입자 맞춤안내, AI 초기상담은 첫 통화에 초점을 둠. 본 제안은 발굴 후 종결된 가구를 대상으로 과거 종결 사유와 반복 발굴 이력을 연결하여 재접촉 필요성을 검토함. 기존 기능과의 중복 여부는 현장 확인이 필요하며, 현재 제안의 차별화 범위는 ‘종결 이후 이력 기반 후속 판단’임.

**② “우선순위가 규칙 기반이라면 AI 혁신성이 부족하지 않은가?”**

LLM은 자유롭게 작성된 종결 메모에서 상태·사유·조치를 추출하고, RAG는 복지서비스 근거를 찾아 상황에 맞는 안내문을 생성함. 우선순위 계산은 담당자가 이유를 검토할 수 있도록 명시적 산식을 적용함. 기술적 차별성은 비정형 기록 해석과 근거 기반 안내를 재접촉 업무에 연결하는 데 있으며, 그 효과는 분류 오류와 검토 부담을 측정하여 확인할 계획임.

**③ “가상 데이터로 평가한 결과를 현장에서 믿을 수 있는가?”**

가상 데이터 평가는 기능의 작동 여부와 정해진 사례에서의 오류를 확인하는 범위로 한정함. 복지서비스 정보는 실제 공개 API를 사용하지만, 상담메모와 발굴이력은 가상 자료임을 명시함. 실제 기록의 표현 다양성, 현장 분류 성능 및 지원 연계 효과는 현장 검토와 별도 실증을 통해 확인해야 함.

**④ “연락을 거부했거나 지원 대상이 아닌 사람에게 다시 연락하는 문제가 생기지 않는가?”**

거부·미응답·연락불가·부적합을 구분하고 일괄 재접촉하지 않도록 설계함. 담당자가 기존 거부 의사, 연락 제한, 부적합 판단이 적용된 제도와 사유, 새 위기신호를 확인한 후 조치 여부를 결정함. AI는 근거와 검토 대상을 제시하며 당사자의 의사와 담당자의 판단을 우선함.

**⑤ “학생 팀이 행복이음 데이터와 시스템 연계를 확보할 수 있는가?”**

현재 구현 범위는 공개 API와 개인정보 없는 가상 이력을 사용하는 독립형 프로토타입임. 행복이음 연계와 운영 데이터 확보를 이미 완료한 것으로 주장하지 않으며, 필요한 항목·화면·처리 절차를 먼저 구현하여 검토 가능한 결과물을 제시함. 가명정보 연계, 기관 내부 대상 확인 및 발송의 구체적인 방식은 제공기관과 시스템 운영 주체의 요건을 확인한 후 결정할 사항임.

### 3. AI 활용방법 및 혁신성

**배분:** 0.80쪽  
**소제목:** 기록의 의미를 읽고, 우선순위를 설명하며, 근거 있는 재안내를 생성

**핵심 문장**

- LLM은 메모에서 업무상태와 종결 사유·조치를 분리하여 추출하고, ‘조사 중’을 완료된 종결로 오인하지 않도록 근거 구절과 확인 필요 여부를 함께 출력함.
- 재접촉 우선순위는 반복 발굴·위기신호 누적·미연결 이력을 중심으로 설명가능한 점수로 제시하며, 고독사 관련 특성의 반영 방식과 가중치는 검증 대상인 설계값으로 관리함.
- RAG는 공개 API에서 확인한 지원 정보를 검색하여 상황에 맞는 후보 2~3개와 쉬운 말 안내문을 생성하되, 정보가 부족한 경우 추가 확인 사항을 표시함.
- 프로토타입에서는 LLM의 비정형 기록 해석·문장 생성과 규칙 기반 점수 계산을 결합하며, 분류 성능·추천 근거 일치·검토 소요시간을 평가하여 개선효과를 제시할 예정임.

## 4. 심사위원 예상 질문 5개와 답변

**① “복지멤버십이나 AI 초기상담과 무엇이 다른가?”**

복지멤버십은 가입자 맞춤안내, AI 초기상담은 첫 통화에 초점을 둠. 본 제안은 발굴 후 종결된 가구를 대상으로 과거 종결 사유와 반복 발굴 이력을 연결하여 재접촉 필요성을 검토함. 기존 기능과의 중복 여부는 현장 확인이 필요하며, 현재 제안의 차별화 범위는 ‘종결 이후 이력 기반 후속 판단’임.

**② “우선순위가 규칙 기반이라면 AI 혁신성이 부족하지 않은가?”**

LLM은 자유롭게 작성된 종결 메모에서 상태·사유·조치를 추출하고, RAG는 복지서비스 근거를 찾아 상황에 맞는 안내문을 생성함. 우선순위 계산은 담당자가 이유를 검토할 수 있도록 명시적 산식을 적용함. 기술적 차별성은 비정형 기록 해석과 근거 기반 안내를 재접촉 업무에 연결하는 데 있으며, 그 효과는 분류 오류와 검토 부담을 측정하여 확인할 계획임.

**③ “가상 데이터로 평가한 결과를 현장에서 믿을 수 있는가?”**

가상 데이터 평가는 기능의 작동 여부와 정해진 사례에서의 오류를 확인하는 범위로 한정함. 복지서비스 정보는 실제 공개 API를 사용하지만, 상담메모와 발굴이력은 가상 자료임을 명시함. 실제 기록의 표현 다양성, 현장 분류 성능 및 지원 연계 효과는 현장 검토와 별도 실증을 통해 확인해야 함.

**④ “연락을 거부했거나 지원 대상이 아닌 사람에게 다시 연락하는 문제가 생기지 않는가?”**

거부·미응답·연락불가·부적합을 구분하고 일괄 재접촉하지 않도록 설계함. 담당자가 기존 거부 의사, 연락 제한, 부적합 판단이 적용된 제도와 사유, 새 위기신호를 확인한 후 조치 여부를 결정함. AI는 근거와 검토 대상을 제시하며 당사자의 의사와 담당자의 판단을 우선함.

**⑤ “학생 팀이 행복이음 데이터와 시스템 연계를 확보할 수 있는가?”**

현재 구현 범위는 공개 API와 개인정보 없는 가상 이력을 사용하는 독립형 프로토타입임. 행복이음 연계와 운영 데이터 확보를 이미 완료한 것으로 주장하지 않으며, 필요한 항목·화면·처리 절차를 먼저 구현하여 검토 가능한 결과물을 제시함. 가명정보 연계, 기관 내부 대상 확인 및 발송의 구체적인 방식은 제공기관과 시스템 운영 주체의 요건을 확인한 후 결정할 사항임.
