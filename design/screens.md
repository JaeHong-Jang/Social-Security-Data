# 이음등 화면 명세 (1단계: 화면 1~3)

슬로건: 다시 찾아갈 곳을 밝히고, 필요한 지원을 잇다. / 사용자: 읍면동 맞춤형복지 담당 공무원 / 1440px 우선, 390px에서도 가로 스크롤 없음.
토큰은 `design/tokens.css`. 시안 이미지는 `design/assets/screen*.png`(실제 브라우저 렌더 캡처, 토큰 적용, 더미 가상 데이터).
기술 전제: React + Vite + TS, 일반 CSS 변수, Pretendard GOV(CDN), lucide-react. 아이콘 이름은 lucide 기준.

## 0. 공통 규칙

### 0.1 시각 방향
- 업무 대시보드 = 「차분한 현장 장부」: 그림자 없음(`--shadow-card:none`), 질감 없음, 모션 없음. 구분은 1px 테두리(`--border-input`)로 한다.
- 소개(화면 0) = 「오려 붙인 기록」: `[data-surface="intro"]` 안에서만 종이 그림자, 세리프 제목, 큰 일러스트를 쓴다.
- 공통: 크림/우드 팔레트, 램프 아이콘, 같은 본문 서체, 같은 종이 오리기 가족 일러스트(`assets/family-papercut.svg`). 업무 화면에서는 빈 상태에만 작게(높이 120px 이하) 쓴다. 데이터 표 안에는 넣지 않는다.

### 0.2 앱 셸(모든 화면)
```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [꺼진램프] 이음등   재검토 대기열 | 기록·성과        [가상 데이터]  ○○구 △△동 복지팀 · 담당자 │ 상단바 64px
├──────────────────────────────────────────────────────────────────────────────┤
│ (본문, max-width 1440, 좌우 여백 24px)                                          │
├──────────────────────────────────────────────────────────────────────────────┤
│ 주최: 한국사회보장정보원 · 대구가톨릭대학교 | 가상 시연용                          │ 푸터
│ 이 화면의 가구·메모는 모두 가상 데이터이며 실제 행복이음 시스템이 아닙니다.        │
└──────────────────────────────────────────────────────────────────────────────┘
```
- "가상 데이터" 표지: 상단바 우측 `Tag`(관찰 계열 outline + `flask-conical`). 항상 보이고 닫을 수 없다. 빨강 금지.
- 로고 자리: 램프 아이콘(24~28px) + 글자 "이음등". **상단바의 램프는 '꺼진' 색**(`--lamp-dome-off`)이다. 빨간 램프가 모든 화면에 상시 켜져 있으면 '긴급'의 의미가 흐려지므로, 램프는 긴급 가구 맥락(가구 상세 머리글, 소개 페이지)에서만 켠다. (결정 사항, 이견 있으면 알려 주십시오)
- 정보원 로고, KRDS 공식 배너, "행복이음" 명칭의 서비스명 사용 금지. 푸터 문구는 위 두 줄로 고정한다.
- 메뉴 탭은 2개(재검토 대기열, 기록·성과). 기록·성과는 1단계에서 비활성(`aria-disabled`, "준비 중"). 선택 탭은 파랑 글자 + 2px 밑줄.
- 포커스 순서 공통: 본문 바로가기 링크("본문으로 건너뛰기") → 메뉴 탭 → 본문 → 푸터.

### 0.3 레드 사용 예산
빨강 계열(`--siren-*`)은 **'긴급' 단계 가구를 가리키는 곳에만** 쓴다. 한 화면에서 빨강 면적은 뷰포트의 5% 이하.

허용(전부):
| # | 위치 | 형태 | 화면 |
|---|---|---|---|
| R1 | 긴급 배지 | solid `--siren-600` + 흰 글자 + `siren` 아이콘 + 글자 "긴급" | 1, 2 |
| R2 | 긴급 행의 왼쪽 바 | 4px, 행 배경은 칠하지 않음 | 1 |
| R3 | 가구 상세 머리글의 램프 | 켜진 램프 24px (긴급 가구일 때만) | 2 |
| R4 | 가구 상세 '긴급 사유' 한 줄 | `--siren-50` 바탕 + `--siren-700` 글자 + 왼쪽 4px 바, 한 문장 | 2 |
| R5 | 소개 페이지 일러스트의 램프 | 정지 상태 | 0 |

금지: 점수 막대와 숫자, 버튼, 링크, 오류 메시지, 연락 거부, 확인 필요, 필터·요약 숫자(예: "긴급 2가구"도 일반 글자색), 토스트, 삭제·취소, 포커스 링, 호버. 오류는 주의 계열 글자 + `circle-alert` + "오류" 글자로 표시한다.
추가 규칙:
1. 긴급이 아닌 가구 상세에서는 R3, R4가 없다(램프는 꺼진 색, 사유 줄은 `--primary-subtle` 안내 줄).
2. 점멸·반복 애니메이션 없음. 새로 긴급이 된 가구가 들어온 직후에만 램프 돔에 1회 `--lamp-glow-ms`(600ms) 빛 번짐을 줄 수 있다. `prefers-reduced-motion`에서는 0ms.
3. 긴급 처리(판단 저장)가 끝나면 배지는 즉시 "처리 완료"(초록 계열)로 바뀌고 R1·R2가 사라진다.
4. 한 행에 배지는 하나만(KRDS). 단계 배지 외의 배지(연락 동의, 메모 해석)는 모두 중립/주의 계열 outline이다.
5. 단계 경계(긴급/주의/관찰)는 F2의 `level` 값을 그대로 쓴다. UI에서 점수로 다시 계산하지 않는다.

| 컴포넌트 | 용도 | 변형 / 규칙 |

| `ReasonChip` | 상위 사유 2개 + 점수 기여(+15) | 중립 outline. 긴 문장은 15자 안팎으로 줄여서 쓰고 전체는 가구 상세에서 본다 |
| `EvidenceHighlight` | 메모 원문 위 근거 구간 | `<mark>` 배경 `--mark-bg` + 2px 밑줄 + 위첨자 번호. 연결된 카드에 포커스가 가면 `--mark-active-bg` + 2px 파랑 외곽선. 색에만 의존하지 않는다 |
| `ConditionTable` | 서비스 조건 대조(조건 / 판정 / 근거) | 판정: 충족 `circle-check` 초록, 미충족 `circle-x` 관찰 계열, 확인 필요 `circle-help` 주의 계열. 미충족을 빨강으로 칠하지 않는다 |
| `DecisionPanel` | 판단 기록 | 라디오 4개 + 사유 입력 + 저장. 1440에서 오른쪽 360px 고정(sticky) |
| `Timeline` | 발굴 → 종결 → 종결 이후 변화 → 오늘 | 세로 목록. 종결 이후 변화는 굵게 + "종결 이후" 소제목 |
| `FairnessNote` | "성별·연령·국적 미사용" 고정 문구 | `ban` 아이콘 + 글자. 화면 2·3 머리글과 점수 구성 하단에 둔다 |
| `NoticeEditor` | 쉬운 말 안내문 초안 편집 | textarea 17px, "AI 초안" 상태 태그, 점수·사유 미포함 문구 |
| `Checklist` | 발송 전 확인 | 체크 3개가 모두 켜져야 "담당자 승인" 활성 |
| `SourceNote` | 출처·조회시각 한 줄 | 15px `--text-subtle` |
| `EmptyState` | 빈 상태 | 작은 가족 일러스트(≤120px) + 문장 1~2줄 + 행동 1개 |
| `Skeleton` | 로딩 | 정지된 회색 막대(깜빡임 없음) + "…하는 중입니다" 글자 |

### 0.5 서체와 카피 규칙
- 본문 17px, 표 16px, 캡션 15px(보조만). 숫자 열은 오른쪽 정렬 + tabular.
- 문장은 "~합니다/~하십시오"체의 간결한 명사형 라벨. 금지: "AI가 똑똑하게", "스마트", "추천드려요", 이모지, 느낌표.
- 점수는 "우선순위 참고값"이며 판정이 아니다. 문구: "이 순서는 담당자의 판단을 돕는 참고이며 대상 여부를 정하지 않습니다."
- AI 산출물은 항상 "AI 초안"으로 표시하고 담당자가 확정하면 "담당자 확인"으로 바꾼다.

목적: 오늘 누구부터 다시 볼지 정한다.

### 1.2 390px
- 표는 카드 목록으로 바뀐다(행 = 카드). 카드 줄 1: 가구 ID(링크) + 동·유형 / 줄 2: 단계 배지 · 점수 · 종결 후 일수 / 줄 3: 연락 동의 · 메모 해석 · 판단 / 줄 4: 사유 칩(줄바꿈 허용).
- 필터는 2열 그리드, 정렬은 한 줄 전체 너비. 요약 줄은 줄바꿈. 긴급 카드는 왼쪽 4px 바 유지. 터치 대상 최소 44px.
- 확인: `assets/screen1-queue-390.png`(scrollWidth 390).

### 1.4 UI 카피
- 제목: 재검토 대기열
- 캡션: 상담 안내로 종결된 가구 중 다시 살펴볼 가구입니다. 점수는 100점 만점의 우선순위이며 성별·연령·국적은 반영하지 않습니다.
- 링크: 정렬 기준 보기 (열면 팝오버: 항목 R·C·W·F·I 배점 표 + "성별·연령·국적 미사용")
- 필터: 종결 후 경과 / 재검토 사유 / 연락 동의 / 판단 상태. 선택 값은 필터 아래 `Tag`로 표시, 각 태그에 "× 해제" 버튼. "필터 모두 해제" 링크.
- 열 머리글: 가구 / 단계 / 재검토 점수 / 재검토 사유(상위 2개) / 종결 후 / 연락 동의 / 메모 해석 / 판단
- 연락 동의 표시: "문자 동의", "방문 동의", "신청 동의"(동의 중 첫 항목 + 나머지는 "외 1건"), "연락 거부", "미확인"
- 페이지: "1–20 / 38가구", 이전, 다음

| 처리 완료 가구 | 판단 열 "재방문" 등 + 단계 배지는 "처리 완료"로 변경, 빨강 제거 |

### 1.6 상호작용
- 기본 정렬: 재검토 점수 높은 순. 정렬 가능 열: 재검토 점수, 종결 후(일). 헤더는 `<button>`, `aria-sort`, 정렬 아이콘 `arrow-up-down`. 숫자 열은 오른쪽 정렬.
- 필터: 선택 즉시 반영. 상태는 URL 쿼리에 보존(뒤로 가기 복귀 시 유지).
- 키보드: 상단 → 본문 바로가기 → 메뉴 탭 → 요약의 "정렬 기준 보기" → 필터 5개 → 표 머리글 정렬 버튼 → 행의 가구 ID 링크(행마다 1개 탭 정지) → 페이지 이동. 팝오버는 Esc로 닫고 포커스를 링크로 되돌린다. 모든 포커스는 `--focus-ring`.
- 표: `caption`, `th scope="col"`. 행 전체 클릭도 상세로 이동하되 접근성 기준은 ID 링크다.

### 2.6 상호작용과 키보드
- 근거 번호(①②③)와 원문 하이라이트는 서로 연결: 번호 링크 클릭/Enter → 원문 구간으로 스크롤 + 활성 하이라이트. 원문의 `<mark>`는 `tabindex="0"`, Enter로 오른쪽 카드의 같은 번호로 이동.
- 포커스 순서: 뒤로 링크 → 머리글 태그(비대화형이라 건너뜀) → 메모 원문의 근거 mark(번호 순) → 메모 해석의 해석 확정/수정 → 점수 구성(비대화형, 키보드 스크롤 가능한 영역은 `tabindex="0"`) → 판단 기록(라디오 그룹 → 사유 → 저장 → 맞춤 재안내 링크).
- 라디오 그룹은 `role="radiogroup"` + 방향키. 저장은 Enter가 아니라 버튼 활성으로만(실수 저장 방지).
- 점수 구성 항목 행은 `dl` 구조. 스크린리더에서 "반복 발굴, 25점 만점에 15점, {사유}"로 읽힌다.

| LLM 실패 | "오류 안내문 초안을 만들지 못했습니다. 직접 작성하십시오." + 빈 편집기(수동 작성 가능) |
| 연락 거부 | 문자=거부면 체크 ① 대신 안내 "문자 연락을 거부한 가구입니다. 문자 안내문은 승인할 수 없습니다." + 버튼 "담당자 승인" 비활성 + "출력용 보기"만 활성(방문·우편 등 담당자가 선택). 방문=거부면 안내문 하단에 "방문 안내는 선택할 수 없습니다." |
| 동의 미확인 | 체크 ①을 "문자 연락 동의 여부를 확인했습니다"로 바꾸고 "미확인" 태그를 함께 표시 |
| API 조회 실패/캐시 사용 | 카드의 출처 줄에 "캐시 사용 · {저장시각}"을 표시, 조회 실패 시 "오류 서비스 정보를 불러오지 못했습니다. 다시 시도" |
| 수정됨 | 편집하면 상태 태그가 "담당자 수정"으로 바뀐다 |

### 3.6 상호작용
- "담당자 승인"은 체크 3개가 모두 켜지고 안내문이 비어 있지 않을 때만 활성(비활성 사유를 버튼 아래 한 줄로 설명).
- 안내문에 점수·단계·위험 문구가 들어 있으면(예: "긴급", "점수") 저장 시 오류 문구로 막는다.
- 포커스 순서: 뒤로 링크 → 후보 카드(카드마다 제목 링크 없음, 내부 비대화형이므로 카드는 `tabindex` 없이 건너뜀; 읽기용 `h2`는 제목 탐색 가능) → 안내문 textarea → 체크 3개 → 담당자 승인 → 출력용 보기. 조건 표는 `caption`(시각적으로 숨김)과 `th scope`.
- 원문 인용은 수정 불가, 안내문만 편집 가능.

### 화면 4. 기록·성과
- 감사 로그 표(시각, 담당자, 가구 ID, 행위, 시스템 제안, 최종 판단, 사유, 규칙·프롬프트 버전, CSV 내보내기).
- 성과 요약(작게): 재검토 처리 건수, 재연계 건수, 평균 처리 시간, 제안 대비 담당자 결정 일치율과 불일치 사유 분포.

## 5. 시각 검수 기록 (실제 브라우저, Chromium, 2026-11-13)
- 1440px: 화면 1·2·3 렌더 확인, 가로 스크롤 없음. 390px: 화면 1·2·3 scrollWidth 390.
- 확인한 점: 긴급 행의 빨강은 왼쪽 바와 배지뿐(행 배경 없음), 단계 배지는 아이콘+글자 병기, 근거 하이라이트는 밑줄 병용, 연락 거부는 빨강이 아님.
- 아직 안 한 것: 화면 2·3의 390px 캡처 육안 확인(scrollWidth만 확인), 다크 모드 렌더, 스크린리더 읽기 순서, 실제 Pretendard GOV 로딩 실패 시 대체 서체.
- 시안의 가구 ID·점수·문구는 모두 임시 가상 값이다. 점수 구성의 합(15+14+15+25+13=82)만 서로 맞췄다.

## 6. 데이터 스키마 쪽에 요청하는 필드 (확인 필요)
1. Decision의 `suggested` (시스템 제안 값). 이 명세는 있다고 가정한다.
2. F2 항목의 짧은 사유(`reason_short`, 15자 안팎, 칩용)와 문장 사유(`reason`, 점수 구성용). 짧은 형이 없으면 UI에서 자르지 않고 문장 전체를 칩 툴팁이 아닌 상세로만 본다.
3. 연락 동의 범위는 가구 단위 + 메모 단위 중 어느 것이 대기열 값인지(이 명세는 가구의 최신 값).
4. F2 `level` 경계값(긴급 비율 상한 여부). 긴급이 너무 많으면 빨강 예산이 깨지므로 운영 기준이 필요하다.
