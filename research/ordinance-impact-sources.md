# 조례 변경 영향 추적: 출처·데이터 가능성 조사

확인일: **2026-11-17**. 공식 가이드·공공데이터포털 원문 HTML과 내장 Swagger, 저장소의 기존 캐시를 구분해 확인했다. **인증키 발급·인증 API 실호출·새 조례 원문 수집은 하지 않았다.**

## 1. 조례 목록·연혁

[국가법령정보 공동활용: 자치법규 목록 가이드](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=ordinListGuide)

- 조례 검색 대상은 target=ordin이며 OC 인증 항목이 있다.
- 현행/연혁 구분, 공포·시행 날짜 범위, 지역, 페이지 조건이 문서화되어 있다.
- 결과에는 법규 ID·일련번호, 법규명, 공포·시행 정보, 지자체, 본문 링크 등이 설명되어 있다.
- display 최대 100은 페이지 크기다. 총 호출 허용량으로 해석하지 않는다.

**설계 적용:** 지역 범위를 좁혀 변경 목록을 찾고 이전·개정 버전쌍의 출처를 보존한다.
실제 연혁 연결, 개칭·폐지·재제정 때 식별자의 안정성, 누락 여부는 실호출로 검증해야 한다.

## 2. 조례 본문·부칙·별표

[국가법령정보 공동활용: 자치법규 본문 가이드](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=ordinInfoGuide)

- target=ordin, OC, ID 또는 MST 등 요청 항목과 본문 응답 항목이 설명되어 있다.
- 본문에는 조문, 부칙, 제·개정문/이유, 공포·시행 관련 정보가 문서화되어 있다.
- **별표는 서울시교육청 및 본청에 한해 제공**한다고 가이드에 적혀 있다. 전국 조례 별표를 모두 API로 받을 수 있다고 가정하지 않는다.

**설계 적용:** 부칙을 별도 적용 근거로 보존하고, 필수 별표·참조 규정이 없으면 근거 확인으로 보류한다. 가이드가 보장하지 않는 조문별 시행일 구조나 완전한 연혁 관계를 만들어내지 않는다.

**미확인:** 실제 계정 인증·호출 한도·이용조건, 과거 버전 조회 성공, 공식 링크의 HTTPS 동작, 첨부 제공 범위. 가이드에 HTTP 예시가 있더라도 운영 인증 정보를 평문 전송하는 설계를 확정하지 않는다. 안전한 연결 방식 확인 전 실제 연동은 보류하고 등록 스냅샷을 사용한다.

## 3. 복지사업과 근거법령 연결

[한국사회보장정보원: 지자체복지서비스 API](https://www.data.go.kr/data/15108347/openapi.do)

공식 페이지의 원문 HTML·내장 Swagger에서 확인한 항목:

| 항목 | 확인 내용 | 용도·제한 |
|---|---|---|
| 목록/상세 | /LcgvWelfarelist, /LcgvWelfaredetailed | 상세는 servId 사용 |
| 서비스 식별·관할 | servId, 사업명·시도/시군구·부서 등 | 사업과 지역 식별에 사용 |
| 설명 | 지원대상·선정기준·신청방법 등 | 비교할 사업 안내 텍스트 |
| 기간·수정일 | enfcBgngYmd, enfcEndYmd, lastModYmd | 사업 시행 기간·최종수정일. 조례 시행일로 대체 금지 |
| 근거법령 | baslawList | 근거법령 목록 존재 |
| 근거법령 하위 항목 | wlfareInfoDtlCd, wlfareInfoReldNm, wlfareInfoReldCn | 각각 상세코드·관련명·관련내용. 법규 ID 전용 필드 아님 |

baslawList의 중첩 항목은 일반 텍스트 렌더에서 누락될 수 있어 내장 스키마까지 확인했다. **자치법규 ID/MST 전용 필드는 확인되지 않았다.** 상세코드를 법규 ID로 쓰거나 관련내용에 항상 법규 링크가 들어온다고 가정하지 않는다. 관할·정식명·사업 근거로 후보를 만든 뒤 연결을 확인해야 한다.

서비스키 필수, 개발·운영 단계 자동승인, 무료·REST·XML, 이용허락범위 “제한 없음”으로 표시되어 있다. 개발계정 트래픽은 **1,000**으로 표기되지만 해당 항목의 기간 단위는 확인되지 않았다. 공통 오류표에 일일·초당 한도 오류는 있으나 구체적인 초당 수치는 확인되지 않는다. 운영계정은 활용사례 등록 후 증설 신청 안내가 있다. 실제 승인 계정의 허용량을 확인한 뒤 수집 속도를 정한다.

위 이용허락범위를 연결된 지자체 웹페이지·첨부파일에 그대로 확대하지 않는다. [공공데이터포털 이용정책](https://www.data.go.kr/ugs/selectPortalPolicyView.do)도 제3자 권리·저작물은 해당 허락조건을 따르도록 안내한다.

## 4. 저장소 기존 캐시의 관측

관측 대상: [서울 지역 기존 캐시](../data/cache/local_서울특별시.json). 신규 API 응답이 아니며 현재 최신성·완전성을 검증하지 않았다.

- items는 397개였다. 상세 자료의 baslawList에는 사전 또는 목록 형태가 있어 입력 정규화가 필요하다.
- 한 항목에서 servId=WLF00005234, 관할=성동구, 근거법령명=“서울특별시 성동구 청년 등 탈모 치료 지원 조례”를 관측했다.
- 이 관측은 사업–법규 연결 후보를 만들 수 있다는 단서다. 해당 조례의 개정·현재 유효성, 안내 오류, 실제 버전쌍의 확보를 뜻하지 않는다.
- 모든 사업 설명이 충분한 법적 근거·적용 시점을 제공한다고 보장하지 않는다.
- 기존 전국 목록 캐시나 이음등 평가 결과를 새 서비스의 데이터 확보·성능 실적으로 계산하지 않는다.

## 5. 수집 전 확인 목록

| 질문 | 현재 상태 | 다음 확인 |
|---|---|---|
| 조례 전후 원문과 부칙을 실제로 확보할 수 있나? | 문서상 항목 확인, 실수집 미검증 | 같은 법규의 연혁 3쌍으로 검증 |
| 사업의 근거법령명을 조례 ID와 연결할 수 있나? | 직접 ID 필드 미확인 | 관할·명칭·원문으로 수동 확인 |
| 비교할 안내자료의 시점을 알 수 있나? | 자료별 미검증 | 현재 안내/과거 공고 구분, 스냅샷 보존 |
| 필수 별표·위임 공고를 확보할 수 있나? | 전국 제공 보장 없음 | 대상 자료별 추가 확보 또는 범위 제외 |
| 각 출처 수집·보관이 허용되는가? | 복지 API 표기 확인, 나머지 미확인 | URL/첨부별 이용조건·안전한 연결 확인 |
| 실제 안내 오류가 존재하는가? | 미입증 | 실제 근거 연결과 업무 검토, 오류 없는 사례도 기록 |

기술 가능성과 실제 업무 가치의 검증은 [검증 계획](../docs/08_validation-plan.md)의 G0에서 시작한다.
