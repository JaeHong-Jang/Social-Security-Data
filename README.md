# 조례 개정에 따른 복지정보 변경 영향 추적 및 안내 오류 예방 AI

조례가 개정되면 영향을 받을 복지사업과 안내자료를 찾고, 변경 근거와 정정 초안을 담당자에게 제시하는 업무 도구다. 현재 실제 자료 탐색·근거 비교와 가상 검토 흐름을 구현했다. AI 분석과 실제 정정 업무는 구현 전이다.

**브랜치:** `design/ordinance-change-impact` · **상태:** 실제 공공자료 연결 + 가상 검토 시연 · **작성일:** 2026-11-17

## 실제 공공자료 화면

실행 주소: **http://127.0.0.1:5175/data**. [수집·서버 실행 방법](prototype/ordinance_impact/README.md)

실제 복지사업 5,289건(기존 목록 캐시), 서울 상세 397건, 조례 7개 버전(전후 3쌍과 제정본 1개), 상위법 1개, 복지로 안내 5건, 공개 통계 2,577행을 연결했다. 공개 원문·연혁·통계는 새로 수집했으며 기존 목록을 최신 API 수집 실적으로 세지 않는다. 출처·원래 관측일·해시·상세 미확보와 실패 상태를 표시한다.

인증키가 없어 복지 API 최신 재조회는 실행하지 않았다. 구청 안내 직접 요청은 차단되어 실패로 남기고, 별도 복지로 공개 안내를 연결했다. 전국의 모든 조례·안내문이나 API 전체 상세를 확보한 상태는 아니다. [실제 출처 조사와 한계](research/ordinance-impact-live-sources.md)

## 가상 검토 시연

변경 검토 목록, 전후 조문·안내문 비교, 정정안 검토·승인, 별도의 수정 확인, 연결·출처·이력을 클릭해 볼 수 있다.
`/impacts`의 검토 자료는 가상 예시다. 실제 데이터 탐색과 분리하며, 가상 승인 상태는 새로고침하면 초기화된다.

## 핵심 흐름

```mermaid
flowchart LR
    A[조례 이전·개정 버전 확보] --> B[조문·조건 변화 추출]
    B --> C[연결된 복지사업 확인]
    C --> D[등록 안내자료 영향 비교]
    D --> E[담당자 정정안 검토]
    E --> F[실제 수정 후 재확인]
```

공포일·시행일·부칙의 적용 조건을 구분한다. 근거가 부족한 건은 확인 요청으로 남기며, AI가 외부 안내문을 자동으로 수정하거나 법적 적용을 확정하지 않는다.

초기 목표는 **한 지자체·복지사업 10개·조례 버전쌍 10개·안내자료 20개**다. 확보된 데이터 수나 달성 성능을 뜻하지 않는다. 먼저 실제 조례–사업–안내자료 연결 3건을 확보해 진행 가능성을 검증한다.

## 저장소 구성

코드는 `prototype/ordinance_impact/`에 있다. `data/cache/`는 수집기가 수입하는 복지서비스 목록·상세 캐시다. 실제 원문 수집·읽기 API는 구현했고, AI 분석·기관 인증·실제 업무 승인은 설계 단계다.
